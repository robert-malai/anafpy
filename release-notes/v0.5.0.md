# anafpy 0.5.0 — one-command ANAF login

## Highlights

**`anafpy auth login` now completes in the browser with no flags and no setup.** ANAF only registers `https://` callback URLs, and no public certificate authority may issue for `localhost` — so until now the login needed either paste mode or a certificate you created yourself. The CLI now generates a **one-time self-signed certificate on the spot** and serves the callback listener with it:

- Run the login, pick your certificate in the browser, click through **one** "connection is not private" warning (the CLI announces it beforehand — it's your machine talking to itself), and the code is captured automatically. Nothing to install, nothing persisted: the key pair lives in memory for that single attempt.
- With logins recurring roughly **once a year** (refresh is headless), that one click is the entire recurring cost.
- Prefer no warning at all? Bring your own trusted certificate with `--tls-cert`/`--tls-key` (e.g. from [mkcert](https://github.com/FiloSottile/mkcert)) — unchanged. `--paste` remains the no-listener fallback, and the CLI still falls back to it automatically if the listener can't start.
- The old silent plain-HTTP default is now the explicit **`--no-tls`** flag (for an external TLS terminator in front of the listener).
- The per-login `state` binding (login-CSRF protection) applies to every capture mode, as before.

**Library**: new `anafpy.auth.tlscert` module — `ephemeral_server_context()` / `generate_self_signed_cert()` (EC P-256, SANs for the redirect host plus both loopbacks, ~24h validity, not a CA). `cryptography` joins the core dependencies.

**Docs**: the setup walkthrough (EN + RO) now leads with the flagless flow — mkcert demoted to an optional "remove the warning" tip — and the `anafpy-setup` skill teaches the same choreography. DESIGN.md records the evaluated-and-rejected alternatives (shipped keys, trust-anchor installation, hosted redirect domains).
