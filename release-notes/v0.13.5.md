# anafpy 0.13.5 — the declaration guides caught up with ANAF, the docs with the code

No change in what the clients do. This release is the documentation — and for
anafpy that is not a side matter, because the documentation ships: the ANAF
reference is served to the assistant as resources, and the workflow skills are
the instructions it follows.

## The declaration guides follow ANAF's current validators

ANAF republished seven validators since the form guides were written. Three of
them changed what a correct declaration looks like:

- **D112** moved to the 07/2026 model (joint order 605/95/928/2314/2026,
  validator `J27.0.8`). The guide describes it — thirteen new attributes, most
  of them for sick leave — and corrects two things it had wrong: the average
  gross salary is 9192 lei from 04/2026, and an ordinary rectification is
  `d_rec="1"` with no `tip_rec`. The examples validate on the current jar for
  June, July and October 2026. ANAF also publishes a schema for this model that
  rejects declarations its own validator accepts; the guide says so, and keeps
  the validator as the authority.
- **D100 and D710** gain obligation code `704`, the contribution on exceptional
  revenue (Legea 162/2026), from the 08/2026 reporting month.
- **D101** was republished without changes; its examples were re-run.

If you file through the assistant, update your validators too — nothing does it
for you. Ask it to *"update DUKIntegrator"*, or run `anafpy duk update`.

Everything else was compared with what ANAF serves today and had not moved: the
26 vendored originals are byte-identical, and so are the e-Transport schema, the
CIUS-RO 1.0.9 rules and BNR's rate schema.

## The workflow skills stopped giving up where the server can help

Two skills told the assistant to stop in situations the server has handled for
several releases:

- **e-Transport** said the server could not log in. It can — it now offers the
  login, and asks for your approval before opening your browser.
- **Declarations** stopped when DUKIntegrator or a form's validator was missing.
  It now offers to install it.

The e-Transport skill also named lookup fields by ANAF's wire names where the
tool answers in English, which could leave a vehicle-change preview with empty
"current" cells.

## The docs were audited against the code

Every page was read against the implementation, and the code was taken as right.
What that turned up, for the pages people act on:

- **Samples that did not run.** `message.message_id` (the field is `id`), a UIT
  card sample missing an import, and a DUKIntegrator sample that crashed when
  the validator was not installed.
- **The setup guides** sent extension users to a terminal to choose their SPV
  certificate, which the assistant does on request. The terminal install is now
  `uv tool install "anafpy[mcp,declaratii,cards]"`: with `anafpy[mcp]` alone,
  declaration signing and the UIT card were missing from a server the guide
  called the same as the extension's.
- **The privacy policy** said data moves only between your computer and ANAF.
  anafpy also asks BNR for exchange rates and, when you sign a declaration,
  fetches your certificate issuer's public certificate. Neither receives
  anything of yours, and both are now named — as are two small files kept on
  your computer that the policy had not listed.
- **The error model** showed the exception classes as siblings.
  `AnafResponseError` subclasses `AnafTransportError`, so catching the latter
  catches every HTTP-level failure as well.

There is a new API page for `anafpy.declaratii`, and the guides now cover a few
things a flow cannot be written without: `MessageStatus.download_id`, the batch
limits on the registry lookups, and the fifteen-minute life of a confirmation
token.

## Not yet verified

- **D112's sick-leave attributes** are transcribed from ANAF's structure annex.
  Of the thirteen new attributes only `E3_97` was exercised on the validator.
- **ANAF's response shapes** were not re-captured for this release. The check
  covered ANAF's published sources; the live tests against e-Factura,
  e-Transport, SPV and StareD112 were not re-run.
