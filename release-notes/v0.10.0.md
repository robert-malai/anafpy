# anafpy 0.10.0 — one-click Claude Desktop install, and beta

This release removes the terminal from the accountant's path entirely. The MCP
server is now packaged as a **Claude Desktop extension** — a single `.mcpb`
file that installs with one click — and the OAuth browser login is served
in-session by a new **`auth_login` tool**, so the last remaining command-line
step is gone. With the surface stable across releases and the project now in
active day-to-day use beyond its author, anafpy also moves from alpha to
**beta**.

## The Claude Desktop extension

`mcpb/` packages the server as a uv-type MCP Bundle: Claude Desktop's managed
uv resolves the released `anafpy[mcp]` at install time — no user Python, no
bundled libraries, no config-file editing. The extension's settings screen
carries everything the server reads from the environment: the ANAF OAuth
Client ID and Secret, the CIF, the OAuth callback URL, and the alternative
`curl.exe` path that unblocks Windows machines with a broken built-in curl
(versions 8.13–8.15) or Windows-on-ARM.

The release pipeline packs and attaches the bundle to every GitHub release
under the constant asset name `anafpy.mcpb`, so
`https://github.com/robert-malai/anafpy/releases/latest/download/anafpy.mcpb`
is a stable install URL from this release onward.

## Terminal-free login: the `auth_login` tool

The OAuth browser login the CLI has always run is now also an MCP tool — ask
Claude to log you in, confirm, and the browser opens for the certificate step.
The tool is deliberately narrower than the CLI: it takes **no credential
parameters** (Client ID and Secret come only from the server's configuration),
has **no paste mode** (an authorization code never transits model context),
makes one attempt per call, and reports failure as `logged_in: false` with
guidance rather than an exception. Since logins recur only roughly yearly,
this one confirmation is the entire recurring cost of the authenticated tools.

Under the hood the login choreography — the state binding, the
bind-before-browser ordering, the code exchange and store save — was
consolidated into `auth/browser.py`'s `browser_login`, the single home behind
both the CLI and the tool. The registered callback URL moved with it:
`anafpy auth login` now defaults to `https://localhost:9002/callback` and
reads `ANAFPY_REDIRECT_URI` exactly like the server, so the "run
`anafpy auth login`" remediation works bare.

## One setup story

The setup skill (`anafpy-setup` plugin) is now **extension-first**: it
installs the release asset and walks the extension settings, keeping the
hand-written `claude_desktop_config.json` route as the repair and fallback
path. The docs grew to match the wider audience: a use-case tour of the MCP
server (`docs/mcp/index.md`), a library-guide index, a contributor quickstart
(`CONTRIBUTING.md`), and a **privacy policy** (`docs/privacy.md`) that the
README and the extension manifest link to. The README itself shrank back to a
landing page that points into the docs site.

## Beta

The PyPI classifier moves to `Development Status :: 4 - Beta`. The scope has
been stable for several releases — thin stateless transport, two-step gated
filing, artifacts to disk — and the project is in real day-to-day use. It
remains `0.x` under SemVer and, as ever, free and as-is.

## Not yet verified

- **The CI-packed extension asset** is first published by this very tag — the
  bundle layout was exercised from local packs, but the
  `releases/latest/download/anafpy.mcpb` route through the release pipeline
  goes live with this release. A one-click install from the published asset
  closes the gap.
- **The `auth_login` tool's first real login**: the choreography it runs is
  the CLI's own, live-proven for months, and the tool contract is covered by
  the mocked suite — but an end-to-end in-session login through a connected
  Claude client on this exact build is what closes this one.
