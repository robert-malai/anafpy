# anafpy 0.5.3 — reverse-charge invoices no longer crash

## Fix

**Authoring a reverse-charge or intra-community invoice crashed.** An `InvoiceDocument` using VAT category E, AE, K, G or O without an explicit `vat_breakdown` made `compute_vat_breakdown()` raise a raw pydantic `ValidationError`, so `validate()`, `render_invoice()`, `compute_totals()`, `upload_invoice()` and the `efactura_prepare_invoice` MCP tool all failed on an everyday exempt invoice. Two contracts broke at once: `validate()` is documented to return findings rather than raise, and the error escaped the `AnafError` hierarchy entirely — the MCP tool surfaced it as a bare `ToolError`.

The cause was a misplaced rule. BR-*-10 (the BT-120/121 exemption reason) looks like a single-model fact, so it was enforced when a breakdown entry is constructed — but the entry is *computed* from the lines whenever you supply none, and a computed entry has nowhere to get a reason. It now moves to `validate()`, which reports it as a fatal finding carrying the official `BR-E/AE/IC/G/O-10` id and says what to do about it; `render_invoice` fails with `InvoiceValidationError` as designed, and `skip_validation=True` still renders and lets ANAF judge. A breakdown entry you write by hand must still carry the reason — that one is data hygiene.

**Four SPV command-line options did nothing.** `--session` on `anafpy spv certs` and `spv select`, and `--identity-file` on `spv status` and `spv logout`, were accepted, advertised in `--help`, and never read: pointing one at a non-default store silently had no effect. Each command now takes only the store it actually uses, so a wrong flag is a visible error instead of a silent no-op. `spv login` genuinely uses both and still accepts both.

## Agent experience

**MCP tool descriptions read as structured text.** Descriptions were assembled by string concatenation, which reaches the model as one unbroken line — the tables inside them were buried in prose. StareD112's four Romanian state wordings, `declaratie_nr_evid`'s per-form inputs, `declaratie_submit`'s three `accepted` verdicts and the nomenclature `kind` lists now render as bullets, so the model has a better shot at picking the right value first time. `declaratie_status` got shorter in the process.

## Internals

No behaviour change, but worth noting if you read the source: the three business-state poll loops now share one `poll_until` helper, the OAuth token store and the SPV session store share their 0600 atomic-write custody, three clients share one non-success raise, and `ServerConfig()` is the single constructor — every misconfiguration now raises `AnafConfigError` rather than pydantic's `ValidationError`, including the paths the tests use.
