# anafpy 0.4.1 — declaration filing from Claude

## Highlights

**Declaration filing lands in the MCP server** — the last M2 piece: the signed declaration PDF can now be filed on ANAF's portal directly from Claude, through the same two-step human-gated flow as the e-Factura and e-Transport filings.

- **`declaratie_prepare` → `declaratie_submit`** — the two-step gate: prepare reads the signed PDF and returns a single-use confirmation token bound to its exact bytes (plus a local heads-up when no embedded signature is detected); submit files only with that token and your explicit `confirm=true`, and returns the portal's verdict with the upload index — which feeds straight into `declaratie_status` / `declaratie_recipisa`.
- **The portal login is its own step, outside the submit cycle** — `declaratie_portal_login` is `confirm`-gated like `spv_login` (it fires your certificate PIN/2FA once), and `declaratie_portal_status` probes the session without ever firing 2FA. `declaratie_submit` re-probes **before** spending the token, so a lapsed session (the portal kills them after ~10 idle minutes) never burns your approval — log in again and the same token still files.
- **Opt-out by design**: declarations file on the **production** portal (there is no test environment), so the filing tools can be removed entirely with `ANAFPY_DECLARATII_UPLOAD=off` — Claude then guides you through manual portal filing instead.
- Honest failure reporting: a portal rejection comes back as a typed outcome with ANAF's reason; an APM bounce on the upload is reported as "nothing was filed"; anything ambiguous is reported as UNKNOWN with an instruction to check StareD112 before ever re-filing.

**Library**: `DeclarationUploadClient` gains `probe()` (a no-2FA session check) and `install_session()` (the seam for externally-run certificate bootstraps).

**Docs**: the declarations documentation wave — the README and library guide now cover the full author→validate→render→sign→file→track pipeline, the setup walkthrough (EN + RO) gained the filing step and the opt-out, and the `declaratie-prepare` workflow skill drives the new filing flow with a per-step approval rule (a signature approval never doubles as the filing approval).
