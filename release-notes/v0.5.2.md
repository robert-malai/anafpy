# anafpy 0.5.2 — one-command DUKIntegrator install

## Feature

**DUKIntegrator now installs itself: `anafpy duk install`.** Filing a declaration needed ANAF's DUKIntegrator distribution, and getting one was the user's problem — download the right archive, unpack it somewhere, point `ANAFPY_DUK_DIR` at it. ANAF's `versiuni.xml` update feed turns out to be self-sufficient: it lists the core jar, the shared and third-party lib jars, and the config files — everything a working dist contains. `anafpy duk install` (and the `declaratie_duk_install` MCP tool) assembles one file by file at `~/.anafpy/duk-dist`; the legacy 90-plus-MB bundle is never downloaded.

A bare install covers the twelve most-used forms plus whatever is already present; `D406T` downloads only when named. Downloads are pinned to `static.anaf.ro` over HTTPS and recorded in a manifest with each file's source URL and SHA-256, so an install is auditable and convergent — current files are skipped and a hand-assembled dist is adopted in place, never wiped. An explicit `ANAFPY_DUK_DIR` still wins everywhere; the managed dist is the fallback.

**Windows can reach Java again.** Java resolution grows a `JAVA_HOME` fallback — `ANAFPY_DUK_JAVA`, then `java` on `PATH`, then `JAVA_HOME/bin/java(.exe)` — because JRE installers there routinely set `JAVA_HOME` without touching `PATH`. `PATH` stays ahead so a stale variable never displaces a working java, and the no-Java error names all three sources. The setup skill's Windows walkthrough gains the declarations half it had deferred, including the honest boundary that signing still needs a Mac.

## Hardening

**DUKIntegrator runs no longer share state.** Every run executes from its own temp directory with a per-run config dir that forces `offLine=Y`, so concurrent runs can't collide and the documented silent-exit-on-update mode can never fire. The rendered PDF is staged in the run directory and moved into place only on success — a killed or failed run leaves no partial file at the caller's path. Err-file encoding is pinned to UTF-8 on every platform, failures with no findings fold the validator log tail into `DukResult.raw`, and findings carry ANAF's official R-number when the message has one.
