# anafpy 0.12.2 — the UIT card stops vouching for an expired day

A correctness release for the e-Transport UIT card, caught by re-reading
ANAF's own documents against what the card prints.

## data_exp_uit is the first expired day

ANAF's API presentation defines the expiry it reports for a UIT verbatim:
*"data incepand cu care UIT-ul este considerat expirat"* — the date **from
which** the code counts as expired, not the last day it may be used. Its
swagger example says the same in numbers (`data_transp` 2024-06-24,
`data_exp_uit` 2024-06-29 — the 5 calendar days of OUG 41/2022 art. 11,
counted from the transport date), and the sources were re-fetched and found
byte-identical to the vendored copies, so this was our reading to fix, not
upstream drift.

The card read it the other way: `data_exp_uit` was printed under
`UIT VALABIL PÂNĂ LA`, and `is_expired` flipped only after the date had
passed — one day too generous, on a code whose use past validity is a
contravention. Now a live card prints the **last valid day**
(`data_exp_uit − 1`, the new `UitCard.last_valid_day`), an expired card
keeps ANAF's own date under `A EXPIRAT LA` (that is when it lapsed), the A4
detail document carries both dates, each labelled, and `is_expired` counts
the expiry date itself as expired. The stored field stays ANAF's value
verbatim — the correction is in what is rendered, never in what is kept.

The same swagger example exposed a second seam: `data_exp_uit` arrives as a
timestamp (`2024-06-29T00:00:00`), which the bare-ISO parse in the MCP card
tools and the CLI's `--expiry` rejected — breaking the exact
lookup-to-card handoff the tool descriptions prescribe. One shared parser
(`parse_uit_expiry`: ISO date, timestamp, or ANAF's compact `YYYYMMDD`) now
sits behind both, so the value is passed on exactly as ANAF returned it.

## The etransport-declare skill, overhauled

The review templates the skill puts in front of the user before filing
could render as raw pipes: their key-value tables carried no header row,
which GFM does not accept as a table. Every table now has one, and the
filing's identity — CIF, operation, correction, post-incident — moved into
the table itself, so the card has no loose header lines left to merge into
a paragraph. The vehicle-change review gained an explicit Current/New
sub-template instead of prose asking the model to invent one.

The test/prod environment banner is gone from the templates: at skill
level it shouldn't matter, and the protection was never the banner — it is
the two-step gate (preview, explicit approval, single-use token), which is
unchanged. After an accepted filing the skill now walks one ordered
hand-over: report the UIT with the obligations that attach to it, read the
expiry back (knowing ANAF scopes that endpoint to the transport organizer,
so a declarant-only filing has no readable expiry — stated, not treated as
an error), always render and present the driver card, and offer the A4
detail document.

## Upgrading

Nothing to migrate. `UitCard.is_expired` flips one day earlier than in
0.12.1 — on ANAF's `data_exp_uit` itself rather than the day after — which
is the point of the release.

## Not yet verified

`uit_expiry` has still never been round-tripped from a real `data_exp_uit`:
the corrected reading rests on ANAF's published definition, its swagger
example, and OUG 41/2022, all re-confirmed against the live documents on
2026-08-28, but no live filing has yet returned the field to a card. The
next real transport closes that loop.
