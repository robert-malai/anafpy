# anafpy 0.9.0 — the clients follow their HTTP stack home

## Breaking change

**Every anafpy client now runs on httpx2** — Pydantic's stewardship
continuation of httpx, under the same original author, honouring the same
design. 0.8.1 noted that httpx2 had arrived as a transitive dependency of the
MCP SDK "and the anafpy clients themselves stay on plain httpx exactly as
before"; this release is the deliberate reversal of that sentence. With the
SDK already on httpx2, every `anafpy[mcp]` install was carrying two parallel
HTTP stacks for no benefit, and classic httpx has meanwhile gone quiet while
its lineage continues under the new name. The dependency is now `httpx2>=2.9`;
classic `httpx` is no longer installed with anafpy.

What this breaks is precisely one thing: **a caller-injected client must now
be an `httpx2.AsyncClient`**, and code that catches httpx exception types off
`AnafError.__cause__`, or subclasses-drives `AnafAuth`/`SpvAuth` with its own
client, must build that client from `httpx2` too. The two packages are
parallel type universes — `httpx2.Response is not httpx.Response`, and an
`except httpx.HTTPError` does not catch httpx2's errors. A classic client
would duck-type at runtime and fail only later, its errors escaping the
`AnafError` hierarchy entirely, so anafpy names the mismatch at construction:
injecting a classic-httpx client raises `AnafConfigError` with the fix in the
message. Nothing else about any client's surface changed — httpx2 2.9 and
httpx 0.28 agree signature-for-signature on everything anafpy touches, from
the `AsyncClient` kwargs through the `Auth` flow protocol to the exception
tree, which is why this migration is a rename and not a rework.

One behavior arrives from below rather than from anafpy: **TLS verification
now uses the operating system's trust store** (httpx2 replaced certifi with
`truststore`). ANAF's hosts present public-CA certificates, so nothing changes
on a clean network — and on corporate networks whose TLS-inspecting proxies
install their root into the OS store, anafpy now works where it previously
needed `SSL_CERT_FILE` workarounds. The wire also shows a new `User-Agent`
(`python-httpx2/…`), and log filtering keyed on the `"httpx"` logger name
should now watch `"httpx2"`.

## Not yet verified

**The live smokes have not yet been re-run on this build.** The respx suite
passes in full, but the suite mocks the wire — and the migration's two
wire-visible changes (the User-Agent string and OS-trust-store verification)
are exactly the kind of thing ANAF's WAF and TLS terminators get opinions
about. The paths to re-confirm before trusting this release in anger: the
public `validare`/`transformare` pair (including the WAF-retry accommodation
on `render_invoice_pdf`), an e-Factura and an e-Transport round-trip against
TEST, an SPV mailbox read over a persisted cookie session, and the declaration
portal's `probe()`.
