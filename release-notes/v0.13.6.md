# anafpy 0.13.6 — a current curl in the Windows extension

A maintenance release with no change in what anafpy does. The Windows
extension's curl moves to the latest release, and the rest of the lock moves to
current versions.

## Why now

On Windows, the extension carries its own `curl.exe`, compiled from a pinned
curl release against Schannel. It is what presents your qualified certificate
from the Windows certificate store during the SPV and declaration-portal logins.
That build was pinned to curl 8.21.0. On 14 October curl 8.23.0 shipped fixes
for fourteen vulnerabilities that affect 8.21.0, and this release compiles
8.23.0 instead.

Most of them do not reach the way anafpy runs curl:

- the build has no HTTP/2, FTP, TFTP or WebSockets;
- the login passes an explicit certificate rather than letting curl pick one
  automatically, which is where the new client-certificate connection-reuse
  mixup lives;
- it never asks for Negotiate authentication, which is behind two of the
  credential leaks.

The fixes that could matter are two availability bugs: a server-set cookie that
aborts loading a cookie jar, and an endless loop when a server leaves out part
of a response. Either could make a login hang or fail, but neither leaks
anything. The macOS extensions use the system's curl and are unaffected. So is
anyone who points `ANAFPY_CURL` at a curl of their own.

`pip-audit` finds no known vulnerabilities in the Python dependencies, before
this release or after it.

## Dependencies

Notable moves in the lock, all exercised by the suite:

- `cyclopts` 5.3 → 5.5. It now derives environment-variable names from
  hyphenated command names with underscores. anafpy names every variable it
  reads explicitly (`ANAFPY_*`), so nothing changes for you.
- `httpx2` 2.16.0 → 2.16.2, bug fixes in redirect handling, `NO_PROXY` matching
  and Digest challenges
- `pydantic` 2.14.4, `pydantic-settings` 2.16.3. The latter fixes symlinks
  being followed out of a secrets directory, which anafpy's configuration does
  not use.
- `pyhanko` 0.38.2, bug fixes
- `w3lib` 2.6, via `parsel` (the StareD112 and portal page reader). It brings in
  a new dependency, `frostwork`, from the same Scrapy maintainers, with wheels
  for every extension target.

## Live-confirmed

The upgraded lock was run against ANAF and BNR before tagging:

- the OAuth token, and the e-Factura and e-Transport listings;
- an e-Factura and an e-Transport filing round-trip on TEST;
- ANAF's `validare`, and `transformare` including the firewall retry;
- the public lookups and BNR's rate feed;
- DUKIntegrator's install, validation and rendering, including the D406T test
  declaration's validation and rendering.

The macOS (Apple silicon) extension was built from the new lock.

## Not yet verified

- **The Windows curl build.** It compiles only on the release workflow's
  Windows runner. The build checks the version banner and Schannel there, but
  the SPV and portal logins were not run with it.
- **The certificate logins**, SPV and the declaration portal. Both fire the
  certificate 2FA and were not re-run. The SPV listing could not be checked
  because the stored session had expired.
- **Signing on a real token** with `pyhanko` 0.38.2. The mocked
  sign-and-validate round-trip passes.
- **StareD112.** ANAF reset every connection to `www.anaf.ro` during the run,
  for plain `curl` and for the previous `httpx2` alike, so the run tells us
  nothing about this release either way.
